## Issues Found

### Issue #1: Knowledge PATCH Restore Missing Ownership Check
**Severity:** Medium
**Location:** `src/app/api/knowledge/[id]/route.ts` line 232
**Description:** PATCH restore action calls `restoreKnowledgeEntry()` without verifying the requesting user is the creator.
**Impact:** Any authenticated user could potentially restore any deleted knowledge entry.
**Recommendation:** Add ownership check before restore:
```typescript
if (action === 'restore') {
  const entry = await restoreKnowledgeEntry(id);
  if (entry?.createdBy !== user.userId) {
    return NextResponse.json({ error: 'Only creator can restore' }, { status: 403 });
  }
}
```

### Issue #2: Knowledge PUT Sharing Settings Risk
**Severity:** Low
**Location:** `src/app/api/knowledge/[id]/route.ts` lines 153-154
**Description:** PUT handler updates `isShared` and `allowEdit` directly from body without owner-only check.
**Impact:** Users with edit permission could modify sharing settings (should be owner-only).
**Recommendation:** Add owner check before allowing sharing field updates.
