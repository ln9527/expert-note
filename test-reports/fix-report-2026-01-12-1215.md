## Fixes Applied

### Fix #1: Knowledge PATCH Restore Missing Ownership Check

**Severity:** Medium

**Symptom:** Any authenticated user could restore any deleted knowledge entry by calling `PATCH /api/knowledge/[id]` with `action: 'restore'`.

**Root Cause:** The PATCH handler called `restoreKnowledgeEntry(id)` without first verifying the requesting user was the creator. The DELETE handler had proper ownership checks, but PATCH was added later without following the same pattern.

**Fix Applied:**
- Added ownership verification before restoring
- Fetch entry first with `getKnowledgeEntryById(id, true)` (includes deleted)
- Check `existing.createdBy !== user.userId`
- Return 403 if non-owner attempts restore

**Files Modified:**
- `src/app/api/knowledge/[id]/route.ts` (lines 243-269)

**Code Change:**
```typescript
// BEFORE (vulnerable)
if (action === 'restore') {
  const entry = await restoreKnowledgeEntry(id);
  // No ownership check!
}

// AFTER (secure)
if (action === 'restore') {
  const existing = await getKnowledgeEntryById(id, true);
  if (!existing) {
    return NextResponse.json({ error: 'Not found' }, { status: 404 });
  }
  if (existing.createdBy !== user.userId) {
    return NextResponse.json({ error: 'Only creator can restore' }, { status: 403 });
  }
  const entry = await restoreKnowledgeEntry(id);
}
```

**Verification:** TypeScript compiles without errors
**Regression Risk:** Low - adds stricter check, no behavior change for legitimate use

### Fix #2: Knowledge PUT Sharing Settings Owner-Only

**Severity:** Low

**Symptom:** Users with edit permission (non-owners) could modify `isShared` and `allowEdit` fields on knowledge entries they don't own.

**Root Cause:** The PUT handler passed `isShared` and `allowEdit` directly from request body to `updateKnowledgeEntry()` without checking if user is owner. The `canEdit` permission check allows non-owners to edit content, but sharing settings should be owner-only.

**Fix Applied:**
- Build update data object conditionally
- Only include `isShared` and `allowEdit` if user is owner
- Non-owners can still update content (background, tags) but not sharing settings

**Files Modified:**
- `src/app/api/knowledge/[id]/route.ts` (lines 149-167)

**Code Change:**
```typescript
// BEFORE (allowed non-owners to change sharing)
const entry = await updateKnowledgeEntry(id, {
  background,
  tagIds: resolvedTagIds,
  isShared,      // Non-owner could change!
  allowEdit,     // Non-owner could change!
});

// AFTER (owner-only for sharing settings)
const updateData = {
  background,
  tagIds: resolvedTagIds,
};

if (isOwner) {
  if (isShared !== undefined) updateData.isShared = isShared;
  if (allowEdit !== undefined) updateData.allowEdit = allowEdit;
}

const entry = await updateKnowledgeEntry(id, updateData);
```

**Verification:** TypeScript compiles without errors
**Regression Risk:** Low - silently ignores sharing fields for non-owners (doesn't error)
