AI 系统 PRD 简化版
技术路线

**前端：**使用 React 和 TypeScript 实现前端界面，提供文档上传、标注和交互功能。

**后端：**使用 Next.js 作为后端框架，处理 API 请求和 AI 模型交互。

**数据存储：**Markdown 文件可以直接作为文件存储，或者使用一个轻量级的索引库（如使用简单的文件索引）来管理文档。

功能需求与交互

文档上传与管理：

用户可以上传原始 Markdown 文件或已有标注的 Markdown 文件。

系统识别文件状态：如果是原始文件，允许用户在前端进行标注；如果是已标注文件，直接进入 AI 处理流程。

### 标注与交互（续）

2. **标注与交互：**  
   - 前端界面采用左右分栏布局：  
     - 左侧：Markdown 原文实时渲染与编辑（支持纯文本与预览切换）。  
     - 右侧：标注工具面板（选择标注类型、层级、原因说明等）。  
   - 支持在文本光标处或选中文本后插入标注，标注以约定的特殊符号直接写入 Markdown。  
   - 标注至少支持三层结构：  
     - **Macro（宏观）**：高层次、强可迁移的原则或判断逻辑。  
     - **Meso（中观）**：面向某一类问题或写作/结构模式的判断。  
     - **Micro（微观）**：针对具体句子、段落或实现细节的修改建议。  
   - 标注完成后，Markdown 文件即为“最终事实源（single source of truth）”。

3. **AI 处理与知识整理：**  
   - 系统内置一个“知识处理 Agent”。  
   - AI 读取两部分信息：  
     - 标注后的 Markdown（核心信号）。
        其中包含原始信息  
   - AI 不负责生成标注，只负责**整理与抽象**标注内容：  
     - 去除具体文本依赖，提炼可复用的判断逻辑。  
     - 区分通用性知识与情境性知识。
     - 其中保留必要的例子和情境，让AI或者人理解这个标注  
   - 输出结构化的知识条目，形成个人/专家知识库。
        -其中包含-标注（遵循原意的基础上进行语言的优化+背景信息）
        -每个文件的标注需要在最前端加入一下背景易于知识的理解

4. **系统提示词（System Prompt）生成：**  
   - 系统内置一个“提示词生成 Agent”。  
   - 该 Agent 的输入包括：  
     - 结构化知识库内容。  
     - 用户选择或配置的生成规则（如用途、风格、约束条件）。  
   - 输出为一个或多个可直接使用的系统提示词版本。  
   - 支持多模板配置（例如：论文评审型、写作教练型、代码审查型等）。

### 输出结果

系统统一支持以下三类输出：

1. **标注后的 Markdown 文件**  
   - 保留所有专家标注与原文内容。  
   - 可直接用于 Cursor、Cloud Code 或其他 AI 工具继续加工。

2. **结构化知识库**  
   - 以条目化形式存储从标注中提炼出的专家判断逻辑。  
   - 可持续累积，跨文档复用。

3. **系统提示词（System Prompt）**  
   - 基于知识库生成。  
   - 可配置、可版本化、可复用。比如，我对论文引言进行了标注，可以生成一个论文引言评论的system prompt

### 简化设计原则

- Markdown 文件即数据本体，不引入复杂数据库结构。  
- 所有高级能力（抽象、归纳、生成）交由大模型完成。  
- 系统重点放在**交互清晰、流程统一、可扩展**，避免过度工程化。  
- 保证学生也可以低成本使用与理解。

## 知识库选择与提示词生成扩展

系统支持根据不同数量的已标注文档动态生成系统提示词。用户可以在生成提示词时选择使用的文档数量范围，例如基于 3 篇、10 篇或更多已标注文档的知识库来生成不同精度和范围的提示词。

这种设计将使提示词随着标注文档数量的增加而更加丰富，用户可以根据不同场景灵活调用更全面或更聚焦的提示词模板，从而提升系统的适应性和实用性。

## 文件管理与存储

本系统支持基于云端为主的文件管理模式，用户在拆分、标注完模块后，所有的片段式 Markdown 文档将默认保存在云端。用户可以在任何设备上访问这些云端文件，实现随时随地的编辑和查看。

此外，系统还提供了将文档片段下载到本地的选项。用户可以根据需要将云端文件导出到本地，以便离线使用或备份。这种方式既保证了所有数据集中管理在云端，又给用户提供了额外的灵活性。

通过这种云端为主、本地为辅的管理方式，用户可以轻松在不同地点和设备之间切换，而所有标注和文档内容都能得到统一管理。

## 空白 Markdown 文档创建与片段粘贴

在文件管理中，系统允许用户创建新的空白 Markdown 文档。用户可以从已上传的完整文档中复制所需的部分内容，并将这些内容粘贴到这个新建的空白 Markdown 文档中。这样，用户可以针对特定的模块或章节进行独立的标注和编辑。

这一功能使得标注过程更加灵活，用户可以在不影响原始文档的情况下，对任意片段进行单独处理。完成标注后，这些独立的 Markdown 文档可以与原文档合并或单独保存，进一步增强了文件管理的灵活性和便捷性。

## 删除与垃圾箱功能

系统还提供了删除文档片段的功能。当用户不再需要某个标注模块或片段时，可以将其删除。被删除的文档片段将被移入系统的垃圾箱中。

在垃圾箱中，用户可以选择永久删除这些片段，或者在需要时恢复它们。这样既能避免误删，也能让用户对所有文档片段有更灵活的管理。垃圾箱功能确保了文档管理的安全性，让用户在处理标注片段时更加安心。
